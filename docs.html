Introduction

Welcome to Nexora. This documentation covers everything you need to build, deploy, and scale your backend using the Nexora platform.

New in v2.0

Nexora v2.0 ships with real-time sync improvements, pgvector support, and a redesigned dashboard. See the changelog →

Nexora is an open-source backend-as-a-service built on Postgres. Each project gets a dedicated Postgres database, instant APIs, auth, real-time subscriptions, storage, and edge functions.

Quickstart

Get up and running in under 2 minutes. Choose your language:

JavaScript
Python
Swift
Kotlin

Install the Nexora client library:

# npm
npm install @nexora/client

# yarn
yarn add @nexora/client

# pnpm
pnpm add @nexora/client

Initialize the client in your app:

import { createClient } from '@nexora/client'

const nexora = createClient(
  process.env.NEXORA_URL,
  process.env.NEXORA_ANON_KEY
)

export default nexora
Tip

Find your project URL and anon key in the Settings → API section of your Nexora dashboard.

Make your first database query:

const { data, error } = await nexora
  .from('products')
  .select('id, name, price')
  .order('created_at', { ascending: false })
  .limit(20)

if (error) throw error
console.log(data)

Install the Nexora Python client:

# pip
pip install nexora-py

# poetry
poetry add nexora-py

Initialize the client:

from nexora import create_client
import os

nexora = create_client(
    os.environ["NEXORA_URL"],
    os.environ["NEXORA_ANON_KEY"]
)

Make your first query:

response = nexora.table("products") \
    .select("id, name, price") \
    .order("created_at", desc=True) \
    .limit(20) \
    .execute()

print(response.data)

Add the Nexora Swift package via SPM:

// Package.swift
.package(url: "https://github.com/nexora/nexora-swift", from: "2.0.0")

Initialize the client:

import Nexora

let nexora = NexoraClient(
    nexoraURL: URL(string: "https://your-project.nexora.io")!,
    nexoraKey: "your-anon-key"
)

Query the database:

let response = try await nexora.database
    .from("products")
    .select("id, name, price")
    .order("created_at", ascending: false)
    .limit(20)
    .execute()

print(response.value)

Add the Nexora Kotlin dependency:

// build.gradle.kts
implementation("io.nexora:nexora-kt:2.0.0")

Initialize the client:

val nexora = createNexoraClient(
    nexoraUrl = "https://your-project.nexora.io",

Query the database:

    .select("id, name, price")

    .execute()

Architecture

Nexora is composed of several open-source components, all orchestrated together:

  • Database — PostgreSQL 16 with pgBouncer for connection pooling
  • API — PostgREST for auto-generated REST, and pg_graphql for GraphQL
  • Auth — GoTrue, a JWT-based auth server
  • Realtime — Elixir-powered WebSocket server listening on Postgres WAL
  • Storage — S3-compatible object store with Postgres access policies
  • Edge Functions — Deno runtime deployed to global edge nodes

CLI Reference

The Nexora CLI lets you manage projects, deploy functions, run migrations, and more — all from your terminal.

Installation

# npm (global)
npm install -g nexora-cli

# Homebrew (macOS)
brew install nexora/tap/nexora-cli

Common commands

# Link a project

# Run migrations locally

# Push schema to remote

# List edge functions

# View logs

Database — Overview

Every Nexora project comes with a dedicated PostgreSQL 16 database. You get direct SQL access, auto-generated REST and GraphQL APIs, real-time change subscriptions, and built-in row-level security — all on top of a fully managed Postgres instance.

Direct access

Connect any Postgres-compatible tool (psql, pgAdmin, Prisma, Drizzle) using the connection string from Settings → Database.

Tables & Views

Create tables using the Nexora Table Editor or raw SQL. Views are automatically exposed through the REST API just like regular tables. 

-- Create a table
CREATE TABLE profiles (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id    uuid REFERENCES auth.users(id) ON DELETE CASCADE,
  username   text UNIQUE NOT NULL,
  avatar_url text,
  updated_at timestamptz DEFAULT now()
);

-- Create a view
CREATE VIEW public_profiles AS
  SELECT id, username, avatar_url
  FROM profiles;

Row-Level Security

Row-Level Security (RLS) lets you define fine-grained access rules at the database level. Nexora generates JWT tokens for every authenticated user, so you can write policies that reference the current user directly in SQL.

Enable RLS on a table

ALTER TABLE posts ENABLE ROW LEVEL SECURITY;

-- Users can only read their own posts
CREATE POLICY "own posts" ON posts
  FOR SELECT
  USING (user_id = auth.uid());

-- Anyone can read published posts
CREATE POLICY "public posts" ON posts
  FOR SELECT
  USING (status = 'published');

Database Functions

PostgreSQL functions (stored procedures) let you encapsulate business logic inside the database. Nexora exposes them automatically via the REST API using rpc. 

-- Create a Postgres function
CREATE OR REPLACE FUNCTION get_user_stats(uid uuid)
RETURNS json
LANGUAGE sql STABLE
AS $$
  SELECT json_build_object(
    'post_count', COUNT(*),
    'latest_post', MAX(created_at)
  ) FROM posts WHERE user_id = uid;
$$;

Call it from your client:

const { data } = await nexora.rpc('get_user_stats', { uid: userId })

Extensions

Nexora supports many popular PostgreSQL extensions out of the box. Enable them from the Database → Extensions panel or via SQL. 

-- Enable pgvector for AI embeddings
CREATE EXTENSION IF NOT EXISTS vector;

-- Enable pg_cron for scheduled jobs
CREATE EXTENSION IF NOT EXISTS pg_cron;

-- Enable uuid-ossp
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

Commonly used extensions include pgvector, pg_cron, postgis, pg_stat_statements, uuid-ossp, and hstore.

Migrations

Nexora uses a file-based migration system compatible with standard Postgres tooling. Each migration is a plain SQL file stored in supabase/migrations/. 

# Create a new migration
nexora migration new add_profiles_table

# Apply pending migrations locally
nexora db reset

# Push migrations to production
nexora db push
Best practice

Always commit migration files to version control. Never edit an existing migration that has already been applied to production — create a new one instead.

Authentication — Overview

Nexora Auth is built on GoTrue and handles user management, sessions, and JWT tokens. It integrates tightly with RLS so your database security stays in sync with your auth state.

Supported providers

Magic Link
Google
GitHub
Discord
Twitter / X
Apple
Microsoft
Phone / SMS
SAML 2.0 SSO

Email & Password

The simplest auth method. Users register with an email and password; Nexora sends a confirmation email automatically. 

// Sign up
const { data, error } = await nexora.auth.signUp({
  email: 'user@example.com',
  password: 'super-secret-password',
})

// Sign in
const { data, error } = await nexora.auth.signInWithPassword({
  email: 'user@example.com',
  password: 'super-secret-password',
})

OAuth Providers

Enable third-party OAuth in your Nexora dashboard under Auth → Providers. Add your OAuth app credentials from each provider. 

// Sign in with Google
const { data, error } = await nexora.auth.signInWithOAuth({
  provider: 'google',
  options: {
    redirectTo: 'https://your-app.com/auth/callback',
  },
})

// GitHub works the same way
await nexora.auth.signInWithOAuth({ provider: 'github' })

Multi-Factor Authentication

Add an extra layer of security with TOTP-based MFA. Users can enroll an authenticator app (Google Authenticator, Authy, etc.) and verify with a 6-digit code on sign-in. 

// Enroll TOTP factor
const { data } = await nexora.auth.mfa.enroll({ factorType: 'totp' })
// data.totp.qr_code — display as QR for the user

// Verify a TOTP code
const { data } = await nexora.auth.mfa.challengeAndVerify({
  factorId: data.id,
  code: '123456',
})

Enterprise SSO

Nexora supports SAML 2.0 for enterprise single sign-on. Configure your identity provider (Okta, Azure AD, Google Workspace) in the Nexora dashboard. 

// Initiate SSO login
const { data, error } = await nexora.auth.signInWithSSO({
  domain: 'yourcompany.com',
})

Edge Functions — Overview

Edge Functions are serverless TypeScript/JavaScript functions deployed to Nexora's global edge network. They run in Deno and have native access to your Nexora project, including the database and auth context.

Deploy your first function

# Install the Nexora CLI
npm install -g nexora-cli

# Login
nexora login

# Create a new function
nexora functions new hello-world

# Deploy it
nexora functions deploy hello-world

Function template

// functions/hello-world/index.ts
import { serve } from "https://deno.land/std/http/server.ts"
import { createClient } from '@nexora/client'

serve(async (req) => {
  const nexora = createClient(
    Deno.env.get('NEXORA_URL')!,
    Deno.env.get('NEXORA_ANON_KEY')!
  )

  return new Response(
    JSON.stringify({ message: 'Hello from Nexora!' }),
    { headers: { 'Content-Type': 'application/json' } }
  )
})

Secrets & Environment Variables

Store sensitive values (API keys, tokens) as secrets — they are injected into your function at runtime and never stored in your code. 

# Set a secret
nexora secrets set STRIPE_SECRET_KEY=sk_live_...

# List all secrets
nexora secrets list

# Access inside a function
const stripeKey = Deno.env.get('STRIPE_SECRET_KEY')

Cron Jobs

Schedule edge functions to run on a recurring basis using standard cron syntax. Define your schedule in the function's config.toml. 

# functions/daily-digest/config.toml
[cron]
schedule = "0 8 * * *"  # Every day at 08:00 UTC

Or use the pg_cron extension directly in Postgres to schedule SQL jobs: 

SELECT cron.schedule(
  'nightly-cleanup',
  '0 2 * * *',
  $$DELETE FROM audit_log WHERE created_at < now() - interval '90 days'$$
);

Realtime — Overview

Nexora Realtime is an Elixir-powered WebSocket server that listens to the Postgres WAL (Write-Ahead Log). Subscribe to any table change — inserts, updates, and deletes — and get live events delivered to connected clients. 

// Subscribe to all changes on the 'messages' table
const channel = nexora
  .channel('messages-changes')
  .on('postgres_changes',
    { event: '*', schema: 'public', table: 'messages' },
    (payload) => console.log(payload)
  )
  .subscribe()

Broadcast

Send ephemeral messages between connected clients without touching the database. Ideal for cursor positions, typing indicators, and live polls. 

const channel = nexora.channel('room-1')

// Listen for broadcasts
channel.on('broadcast', { event: 'cursor' }, ({ payload }) => {
  renderCursor(payload)
}).subscribe()

// Send a broadcast
channel.send({
  type: 'broadcast',
  event: 'cursor',
  payload: { x: 42, y: 100 },
})

Presence

Track which clients are currently connected to a channel. Perfect for "who's online" features and collaborative editors. 

const channel = nexora.channel('room-1')

channel
  .on('presence', { event: 'sync' }, () => {
    const state = channel.presenceState()
    console.log('Online:', Object.keys(state))
  })
  .subscribe(async (status) => {
    if (status === 'SUBSCRIBED') {
      await channel.track({ user_id: currentUser.id })
    }
  })

Storage — Overview

Nexora Storage is an S3-compatible object store. Create buckets, upload files, and serve them via a global CDN — all protected by the same Postgres-based access policies you use for your database. 

// Create a bucket
const { data, error } = await nexora.storage.createBucket('avatars', {
  public: false,
  allowedMimeTypes: ['image/png', 'image/jpeg', 'image/webp'],
  fileSizeLimit: '5MB',
})

Uploads

Upload files directly from the browser or from your server. Nexora validates MIME type and file size automatically against your bucket's policy. 

// Upload a file
const { data, error } = await nexora.storage
  .from('avatars')
  .upload(`public/${userId}.webp`, fileBlob, {
    cacheControl: '3600',
    upsert: true,
  })

// Get a public URL
const { data: { publicUrl } } = nexora.storage
  .from('avatars')
  .getPublicUrl(`public/${userId}.webp`)

CDN & Transform

Nexora serves files via a global CDN. Use the built-in image transformation API to resize, crop, and convert images on the fly — no extra service needed. 

// Get a transformed image URL
const { data: { publicUrl } } = nexora.storage
  .from('avatars')
  .getPublicUrl(`public/${userId}.webp`, {
    transform: {
      width: 200,
      height: 200,
      resize: 'cover',
      format: 'webp',
      quality: 80,
    },
  })

Self-hosting — Docker

Run the entire Nexora stack locally or on your own infrastructure using Docker Compose. The official compose file starts all services with a single command. 

# Clone the self-hosting repo
git clone https://github.com/nexora/nexora

cd nexora/docker

# Copy and edit the env file
cp .env.example .env

# Start all services
docker compose up -d
Requirements

Docker Desktop 4.x or Docker Engine 24+ with Compose v2. At least 2 GB of RAM recommended.

Kubernetes

Deploy Nexora on Kubernetes using the official Helm chart. Supports horizontal scaling for stateless services and managed Postgres via an external RDS or Cloud SQL instance. 

# Add the Nexora Helm repo
helm repo add nexora https://charts.nexora.io
helm repo update

# Install
helm install nexora nexora/nexora \
  --namespace nexora \
  --create-namespace \
  --values values.yaml

Configuration

All Nexora services are configured via environment variables. The most important ones are listed below. 

# Postgres
POSTGRES_PASSWORD=your-super-secret-password

# API
NEXORA_URL=http://localhost:8000
NEXORA_ANON_KEY=<your-anon-key>
NEXORA_SERVICE_ROLE_KEY=<your-service-role-key>

# JWT
JWT_SECRET=your-jwt-secret-min-32-chars
JWT_EXPIRY=3600

# Email (SMTP)
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=admin@example.com
SMTP_PASS=smtp-password
SMTP_SENDER_NAME=Nexora
